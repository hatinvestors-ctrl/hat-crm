# rehab-engine

## Purpose

Single source of truth for renovation budget bracketing (light/medium/heavy cost
ranges by condition) and the "max reno budget that still makes the deal work"
solver used when renovation cost is unknown. Today this logic is narrative-only,
generated by AI inline in `generate-core-analysis.mjs`, `generate-ai-notes.mjs`,
and `estimate-reno.mjs`, each with its own cost bands.

## Responsibilities

- Bracket a condition description (light/medium/heavy/unknown) into a cost range
  from `config/rehab.config.ts`.
- Solve for the maximum renovation budget that keeps a BRRRR or flip deal viable at
  a given price, using `config/financial.config.ts` for deal-level thresholds
  (MAO formula, selling costs) together with `config/rehab.config.ts` for the
  condition-tier cost bands.
- Reconcile estimated vs actual renovation line-item costs (`deal_renovation_items`)
  for future evaluation (see `history/README.md`).

## What belongs here

- `bracketRehabCost(tier, rehabConfig) → RehabCostBracket`
- `computeMaxRehabBudget(askingPrice, arv, financialConfig, rehabConfig) → MaxRehabBudgetResult`

## What must NEVER belong here

- Condition *interpretation* from free text — that remains a genuine AI judgment
  call (see architecture doc Step 5/§B "AI reasoning"); this engine only does the
  arithmetic once a condition tier is known.
- Any LLM call.

## Sprint 1.1 correction

**Sprint 1 originally implied this engine would read cost brackets from
`config/financial.config.ts`.** Architecture review flagged this as a mismatch:
`FinancialConfig` was designed to hold purchase/holding/selling-cost assumptions,
not renovation cost bands, and never defined them. `config/rehab.config.ts` was
added specifically to hold `RehabCostBracket`/`ConditionTier` definitions, and this
engine's interfaces (`index.ts`) now import from `rehab.config.ts` instead. This
engine still uses `FinancialConfig` where it genuinely needs deal-level math (the
MAO/selling-cost thresholds `computeMaxRehabBudget` solves against) — that part of
the dependency was correct and is unchanged.
